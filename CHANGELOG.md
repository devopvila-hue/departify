- Automatic Department onboarding in Sprint 48. The `organization.provisioned` handler in `packages/business-events` now runs the `wf_department_onboarding` workflow (Sprint 47) automatically after a successful activation + discovery — the Empresa Digital starts working and delivers its first value without a manual trigger, completing the Vending Machine flow (provisioning → Golden Image → Empresa Digital → Department onboarding → first value). `buildDefaultCatalogHandlers` accepts an optional `onboardingEmployeeAgentId` (default `agent_lead_qualifier`); the handler appends the onboarding result to the output (`{ activation, discovery, onboarding }`) and reports the onboarding as the final workflow. Fully retro-compatible: without a discovery workflow the behavior is unchanged (activation only), and a failed activation or discovery short-circuits the onboarding. - Department Onboarding workflow in Sprint 47. Adds the `wf_department_onboarding` official workflow to `packages/workflows`: a single trigger that runs the whole work pipeline of a freshly provisioned Department and delivers its first value — the Vending Machine step. This reduces the distance between "Empresa Digital creada" and "primer valor entregado" towards the Vending Machine vision. 4 new tests (3 unit + 1 end-to-end: Director + Employee → real Tool Runtime → real catalog tools → first value). The Business Discovery lifecycle stays closed and frozen — no new `discovery.*` capabilities. Existing public contracts of every other package are untouched.

New components: `BusinessEventCatalog` (the **only authorised source** for event → handler mapping; no reflection, no dynamic discovery), `BusinessEventService` (the single composition entry point; idempotent by eventId; never executes business logic directly). Three default catalog handlers dispatch to existing runtimes: `lead.created → wf_lead_qualification` (Workflow Execution), `organization.created → business provisioning` (Business Provisioning Service), `organization.provisioned → initial company activation`. Every result carries the full correlation chain (eventId, workflowId, executionId, provisioningId, departmentId, organizationId, timestamps, errors). 16 tests (6 catalog + 8 service + 2 end-to-end). No IA, no LLM Router, no HTTP, no SDKs, no Fastify/Supabase/Docker, no new runtimes/bridges/motors. Existing public contracts of every other package are untouched.
